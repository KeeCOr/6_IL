InisLand

  • 문서 유형: 게임
  • 문서 버전: 1.0
  • 프로젝트 버전: 0.1.0 (package.json 기준, portable exe는 v0.3.0 별도 표기 — 불일치 미해소)
  • 근거 신뢰도: low

1. 문서 메타데이터와 근거 범례

  • [사실] 문서 버전 1.0. 프로젝트 버전은 package.json 0.1.0과 InisLand_v0.3.0_portable.exe 파일명 간 불일치가 관측됨(원인 미확인).
  • [사실] Unity 트랙(.sln, .csproj, unity-*.log)과 웹 트랙(Phaser+bitecs+Vite) 산출물이 동일 루트에 공존.
  • 범례: [사실]=파일명/코드/로그로 직접 확인, [제안]=본문 미확인 상태에서의 설계 제안(구현/검증 여부 불명).
  • [미확인] 핵심 기획서·구현분석·페르소나 문서 본문은 이번 세션에서 열람하지 못해 인용 불가.

2. 문제 정의

  • [제안] 눈 덮인 판타지 중세 배경에서, 플레이어가 소규모 정착지를 방어하며 자동 전투형 생존을 이어가는 동안 '기지 유지'와 '전투 확장'을 동시에 관리하기 어렵다는 문제를 겨냥하는 것으로 추정(package.json description 근거).
  • [미확인] 구체적 페인 포인트(예: 기존 VS류 게임과의 차별점, 콜로니 시스템 부재 등)는 InisLand_기획서.md 본문 확인 필요.

3. 한 줄 피치와 제품 포지셔닝

  • [사실] package.json description 원문: "Snowfield colony survival + auto-battler. Fantasy medieval VS-like."
  • [제안] 포지셔닝: Vampire Survivors류 오토배틀 루프에 콜로니(정착지) 생존·자원 관리 레이어를 결합한 판타지 중세 서바이벌로 추정.

4. 주 페르소나

  • [제안] 이름: 한지우, 29세, 주 4일 근무 사무직. 퇴근 후 20~30분 단위로 짧게 즐기는 오토배틀러/서바이벌 장르 라이트 게이머라는 맥락으로 설정.
  • [미확인] 실제 페르소나 정의는 InisLand_페르소나_플레이_피드백_v0.2.0.md, persona_playtest_feedback.md에 있을 가능성이 높으나 본문 미확인으로 위 인물상은 제안 단계임.

5. 디자인 기둥과 핵심 재미

  • [제안] (1) 짧은 세션 내 성장 체감, (2) 자동 전투 중 자원/기지 관리 결정, (3) 눈밭 환경에 따른 시야·조명 변화 대응(코드상 DayNightLightCalcTests.cs, LightFlickerTests.cs 존재로 주야/광원 시스템 실재 확인).
  • [사실] 주야 조명 계산 및 라이트 플리커 로직에 대한 테스트 파일이 존재 — 해당 시스템이 핵심 재미 요소 중 하나로 다뤄지고 있음을 시사.

6. 핵심 루프

유저가 선택을 하면 결과가 되고, 그 결과 때문에 다시 선택을 한다.

  • [제안] 정확 순환 문장: "플레이어는 낮 동안 자원을 채집하고 기지를 강화한 뒤, 밤이 되면 몰려오는 몬스터를 자동 전투로 방어하고, 생존 후 보상으로 다시 낮의 채집·강화를 반복한다."
  • [미확인] 실제 루프 상세(자원 종류, 강화 트리 등)는 기획서 본문 필요.

7. 최초 30초 플레이 흐름

  • [미확인] 온보딩/튜토리얼 흐름을 코드나 로그에서 직접 확인하지 못함.
  • [제안] 타이틀 진입 → 낮 페이즈 시작 안내(HUD 가이던스 텍스트 노출, HudGuidanceTextTests.cs/unity-hud-guidance-*.log 존재로 가이던스 기능 실재 추정) → 첫 자원 채집 상호작용 유도 순으로 추정.

8. 게임 규칙과 승패 조건

  • [미확인] 승패 조건, 웨이브 종료 조건 등 규칙 본문 미확인.
  • [제안] 기지 체력 0 도달 시 패배, 특정 밤(웨이브) 생존 시 라운드 클리어 구조로 추정.

9. 콘텐츠, 진행, 성장, 경제 구조

  • [미확인] 콘텐츠 수량, 진행 트리, 경제 밸런스는 근거 문서 본문 없이 확인 불가하며 임의 수치는 기재하지 않음.
  • [사실] 시스템 존재가 코드로 확인된 항목: 주야 전환(라이트 계산), HUD 가이던스 텍스트. 그 외 성장/경제 요소는 미확인.

10. MVP 가설과 검증 방법

  • [제안] 가설 1: 주야 전환에 따른 위협 변화(라이트/몹 스폰)가 세션 반복 동기를 만든다 — 검증: 플레이테스트 세션당 재도전 횟수 기록.
  • [제안] 가설 2: HUD 가이던스 텍스트가 신규 유저의 첫 루프 이해도를 높인다 — 검증: 가이던스 노출 여부별 30초 내 첫 행동 성공률 비교.
  • [미확인] 실제 검증 결과(플레이테스트 데이터)는 본문 미확인으로 기재하지 않음.

11. 레퍼런스별 핵심 행동 단계 수와 적용 교훈

  • [제안] Vampire Survivors류: 핵심 행동 3단계(이동 회피 → 자동 공격 성장 선택 → 웨이브 생존) — 교훈: 선택은 최소화하고 성장 피드백은 즉각적이어야 함.
  • [제안] 콜로니 서바이벌류(예: 방치형 기지 방어작): 핵심 행동 4단계(자원 채집 → 건설/강화 → 방어 배치 → 웨이브 방어) — 교훈: 낮/밤 페이즈 분리가 관리와 전투의 인지 부하를 나눔.
  • [미확인] InisLand가 실제 참조한 레퍼런스 목록은 기획서 본문 확인 필요.

12. 수치 KPI와 측정 방법

  • [제안] KPI 검증 목표 1: 첫 세션 15분 리텐션 40% 이상 — 측정: 세션 시작~15분 시점 활성 여부 로그 기반 비율 산출(측정 인프라 존재 여부 미확인).
  • [제안] KPI 검증 목표 2: 신규 유저 첫 밤 페이즈 생존율 60% 이상 — 측정: 낮→밤 전환 이벤트와 밤 종료(생존/패배) 이벤트 매칭.
  • [미확인] 실제 계측/애널리틱스 구현 여부는 코드에서 확인하지 못함(위 두 항목은 제안 목표치이며 실측 데이터 아님).

13. UI, HUD, 컨트롤

  • [사실] HUD 가이던스 텍스트 기능이 Assets/Scripts/Tests/HudGuidanceTextTests.cs 및 다수의 unity-hud-guidance-*.log, TestResults-HudGuidance*.log로 존재 확인.
  • [제안] 5가지 UI 상태: (1) 로딩/초기화 화면, (2) 낮 페이즈 관리 HUD(자원/건설), (3) 밤 페이즈 전투 HUD(체력/웨이브 진행), (4) 결과(승/패) 화면, (5) 가이던스 툴팁 오버레이 상태.
  • [미확인] 컨트롤 스킴(키보드/게임패드/터치) 상세는 본문 미확인.

14. 로딩·빈 상태·에러·100개 이상 데이터·3배 긴 텍스트 대응

  • [미확인] 위 항목들에 대한 구체적 처리 로직은 코드/로그로 확인하지 못함.
  • [제안] HUD 가이던스 텍스트 시스템이 존재하므로, 3배 긴 텍스트(다국어 등) 대응 시 해당 텍스트 컴포넌트의 줄바꿈/말줄임 처리 검증이 필요하다는 점만 제안으로 남김.

15. 접근성

  • [미확인] 색맹 모드, 자막, 컨트롤 리매핑 등 접근성 기능 여부를 확인할 근거를 찾지 못함.
  • [제안] 주야 라이트 플리커(LightFlickerTests.cs) 연출은 광과민성 사용자를 위한 강도 조절 옵션 검토가 필요.

16. 시각·청각·햅틱 피드백

  • [사실] sfx-vfx-candidates-20260808.md 문서가 존재해 SFX/VFX 후보 검토가 진행 중임을 시사(본문 미확인).
  • [제안] 밤 페이즈 전환, 웨이브 생존/패배 시점에 시청각 피드백 강화가 필요할 것으로 추정.

17. 구현 상태 매트릭스

  • [사실] 구현 확인됨: 주야 라이트 계산(DayNightLightCalcTests.cs), 라이트 플리커(LightFlickerTests.cs), HUD 가이던스 텍스트(HudGuidanceTextTests.cs).
  • [사실] 산출물만 확인: 웹(Phaser+bitecs) 빌드 스크립트, Unity 빌드 로그 다수, 포터블 실행파일(v0.3.0).
  • [미확인] 그 외 콘텐츠(자원/건설/경제 시스템)의 구현 여부는 근거 부족으로 상태 판정 불가.

18. 빌드·테스트 근거

  • [사실] 웹: package.json에 build(tsc --noEmit && vite build), test(vitest run) 스크립트 존재.
  • [사실] Unity: unity-build-windows*.log(4종, 일부 retry/escalated 포함), unity-editmode-tests.log, unity-test.log, unity-verify.log, unity-implement-verify.log, unity-implementation-parity.log, unity-hud-guidance-red.log/green.log/final.log, TestResults-HudGuidance.log, TestResults-HudGuidance-editmode.log 등 다수 로그 파일이 루트에 존재.
  • [미확인] 위 로그들의 실제 통과/실패 결과 본문은 이번 세션에서 열람하지 못해 성공 여부를 단정하지 않음.

19. 알려진 리스크와 실패 시나리오

  • [사실] 버전 표기 불일치(package.json 0.1.0 vs portable exe v0.3.0)는 배포/문서 관리 리스크로 관측됨.
  • [사실] Unity 빌드 로그명에 retry, retry2, escalated 표기가 존재 — 과거 빌드 실패 후 재시도 이력이 있었음을 시사(구체 원인은 본문 미확인).
  • [제안] 웹(Phaser)과 Unity 두 구현 트랙이 동시 존재함에 따른 유지보수 이원화 리스크.
